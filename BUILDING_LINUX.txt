Building Linux Kernel 6.9 with ggcc (Stage C1)
================================================

This document details the step-by-step procedure for compiling Linux Kernel 6.9
for ARM64 using ggcc inside a Linux Docker environment and booting it under QEMU.

Clean-room guarantee: ggcc emits textual assembly (.s) for all C source files.
Kernel .c files are NEVER compiled by system gcc or clang.

------------------------------------------------
0. Prerequisites
------------------------------------------------

  - Rust stable (cargo build --release)
  - Docker Desktop / Docker Engine with linux/arm64 container support
  - qemu-system-aarch64 installed on host or inside container

------------------------------------------------
1. Build ggcc (Linux Target Binary)
------------------------------------------------

  cargo build --release

  For containerized builds, the build harness sets CARGO_TARGET_DIR=target-linux
  producing the Linux ELF ggcc binary at:

    target-linux/release/ggcc

------------------------------------------------
2. Fetch Linux 6.9 Source Tree
------------------------------------------------

  mkdir -p third_party
  cd third_party
  curl -fL -o linux-6.9.tar.xz \
    https://cdn.kernel.org/pub/linux/kernel/v6.x/linux-6.9.tar.xz
  tar -xJf linux-6.9.tar.xz
  # Source tree extracts to: third_party/linux-6.9/ (gitignored)

------------------------------------------------
3. Policy Environment Configuration (PASS Path)
------------------------------------------------

  export GGCC_ALLOW_SOFT_SYSCC=0          # Hard error if external C compiler invoked on .c
  export GGCC_SOFT_FREESTANDING=0         # Mid-boot soft body-skip disabled

------------------------------------------------
4. Automated Docker Kernel Build
------------------------------------------------

  From project root:

    ./harness/docker/build_kernel.sh

  Build steps executed internally:
    - Builds Docker image `ggcc-linux` from `harness/docker/Dockerfile.linux`
    - Compiles `ggcc` for Linux ARM64 target inside container
    - Sets `CC=harness/docker/ggcc_cc_wrapper.sh`
    - Runs `make ARCH=arm64 CC=$WRAP HOSTCC=gcc defconfig Image`

  Wrapper rules:
    - User `.c` files → `ggcc -S` → system `as`/`cc` on emitted `.s` ONLY
    - Assembly (`.S`/`.s`) and objects (`.o`) → system toolchain
    - If `GGCC_ALLOW_SOFT_SYSCC=1` is passed → hard error

------------------------------------------------
5. Manual Compilation Command (Inside Linux aarch64 container)
------------------------------------------------

  export GGCC=$PWD/target-linux/release/ggcc
  export GGCC_TARGET_OS=linux GGCC_ARCH=aarch64
  export GGCC_SOFT_FREESTANDING=0 GGCC_ALLOW_SOFT_SYSCC=0
  WRAP=$PWD/harness/docker/ggcc_cc_wrapper.sh
  chmod +x "$WRAP"

  cd third_party/linux-6.9
  make ARCH=arm64 defconfig
  make ARCH=arm64 CC="$WRAP" HOSTCC=gcc HOSTCXX=g++ -j$(nproc) Image

  Output Kernel Image location:
    arch/arm64/boot/Image (Size: ~17.74 MB; vmlinux ELF size: ~63.96 MB)

------------------------------------------------
6. QEMU Boot Verification
------------------------------------------------

  qemu-system-aarch64 -M virt -cpu cortex-a57 \
    -kernel arch/arm64/boot/Image \
    -nographic \
    -append "console=ttyAMA0 earlycon=pl011,0x9000000"

  Expected output markers:
    - `Linux version 6.9.0 ...`
    - System initialization (MMU, page tables, memory zones, SMP CPUs)
    - Execution of userspace PID 1 binary (`ggcc-init`)

------------------------------------------------
7. Anti-Bypass & Clean-Room Verification
------------------------------------------------

  ./scripts/anti_bypass_audit.sh
  ./harness/mutation_check.sh

  Verification check:
    strings arch/arm64/boot/Image | grep freestanding
    # Must yield 0 freestanding body skips on PASS path.

------------------------------------------------
8. Definition of Stage C1 PASS
------------------------------------------------

  Stage C1 PASS requires:
    1. Clean-room kernel build (`make_ec = 0` with zero soft SYSCC fallback).
    2. Verified QEMU boot execution demonstrating MMU init and PID 1 start.
    3. Audit logs saved to `scratch/stage_c_kernel.log` and `scratch/qemu_boot.log`.
